# Research: Interactive graph engine and layout stack

## Summary

Select **yFiles for HTML 3.x as the graph engine and its Hierarchical Layout as the layout stack**, subject to purchasing a commercial license. It is the only maintained candidate reviewed that documents the whole required path—framework-neutral/Web Component integration, nested group nodes, mature compound-aware hierarchical layout, dark product-level SVG styling, hundreds-of-elements performance, explicit SVG and PNG export, and an ARIA accessibility pattern—without relying on an unmaintained export plug-in or a second layout adapter.

If commercial licensing is categorically unavailable, the open-source fallback is **Cytoscape.js + ELK.js**, but it does **not** meet the first-release SVG requirement as a wholly maintained stack: Cytoscape.js exports PNG/JPG natively, while SVG depends on the old third-party `cytoscape-svg` extension. That fallback should therefore be selected only after either changing the SVG requirement or successfully owning and validating an SVG exporter.

## Findings

1. **yFiles is the lowest implementation-risk fit.** Its graph model explicitly supports parent groups and children, and applying a layout automatically transfers group information, insets, and minimum-size constraints. The official Web Components demo proves that `GraphComponent` can live in a custom element and Shadow DOM, which maps directly to a Lit component boundary. [Group-node layout model](https://docs.yfiles.com/yfiles-html/dguide/layout_graph_api-structure/) · [Web Components demo](https://live.yworks.com/demos/toolkit/webcomponents/)

2. **Its default rendering and scale guidance match this product target.** yFiles defaults to SVG for CSS styling, crisp text, hover effects and animation, while also supporting Canvas and WebGL2. Its performance guide says graphs with “up to a few hundred elements” normally work well without dedicated optimization and reserves its large-graph techniques for thousands or tens of thousands; 500 is near enough to require a representative benchmark, not a renderer redesign. [Canvas/SVG rendering](https://docs.yfiles.com/yfiles-html/dguide/html_canvas/) · [Large-graph performance](https://docs.yfiles.com/yfiles-html/dguide/large_graph_performance/)

3. **yFiles alone provides first-party evidence for both required export formats.** `SvgExport` exports a whole graph or viewport as SVG, and the official Image Export path uses browser canvas capabilities to produce PNG. [Image export](https://docs.yfiles.com/yfiles-html/dguide/io-image_export/)

4. **yFiles has the strongest accessibility starting point, but no canvas should be the sole accessible representation.** yWorks ships an official demo that assigns ARIA attributes to graph items. BaiZeArchitect should still specify keyboard traversal, visible focus, selection announcements, and an equivalent inspector/list because spatial diagrams are not inherently understandable to screen readers. [Accessibility with ARIA demo](https://www.yfiles.com/demos/application-features/accessibility/)

5. **The trade-off is procurement, not technical capability.** yFiles is commercial: yWorks documents a one-time perpetual purchase with optional annual maintenance, with license scope tied to developers/applications. Approval and an evaluation package are prerequisites before implementation planning can treat this selection as executable. [Official pricing and licensing](https://www.yfiles.com/pricing)

6. **Cytoscape.js + ELK.js is the strongest open-source fallback.** Cytoscape models compounds directly through node `parent` fields and offers stylesheets, selection/events, gestures and native PNG export. ELK Layered provides hierarchical layout and orthogonal/spline routing, and ELK.js supports browser Web Workers so layout need not freeze Lit’s UI. [Cytoscape.js API](https://js.cytoscape.org/) · [ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html) · [ELK.js worker usage](https://github.com/kieler/elkjs)

7. **Do not use `cytoscape-elk` unchanged for the production path.** The first-party adapter does preserve Cytoscape parent/child hierarchy, but its source creates `new ELK()` from the bundled build on the calling thread and currently puts every edge at the root with a TODO about edge cases. A production fallback should run direct `elkjs/lib/elk-api` in a Vite worker, then apply returned coordinates through Cytoscape’s `preset` layout. [Adapter source](https://github.com/cytoscape/cytoscape.js-elk/blob/master/src/layout.js) · [ELK.js worker usage](https://github.com/kieler/elkjs)

8. **Cytoscape’s blocking deficiency is SVG export.** Core documentation exposes `cy.png()`/`cy.jpg()` but no `cy.svg()`. The `cytoscape-svg` extension can add SVG export, but it is a separate third-party repository with an old dependency range (`Cytoscape.js ^3.2.0`) and should not silently become a first-release reliability dependency. This is a **high-severity requirement risk**, not a minor integration detail. [Cytoscape export API](https://js.cytoscape.org/#core/export) · [`cytoscape-svg` repository](https://github.com/kinimesi/cytoscape-svg)

9. **Cytoscape should still be benchmarked conservatively at 500 visible nodes.** Its official performance guide says compound nodes, labels, complex edge styles, arrows and high pixel ratios add cost, and recommends batching, limiting labels by zoom, and simplifying edges. The benchmark fixture must include realistic C4 nesting and relationship density rather than 500 plain circles. [Cytoscape performance guidance](https://github.com/cytoscape/cytoscape.js/blob/master/documentation/md/performance.md)

10. **G6 is a credible but second-ranked OSS alternative.** Its first-party materials document Combo elements, a combo-aware layout, Canvas/SVG/WebGL rendering, dark themes, and active 5.x releases. However, the reviewed first-party export API promises DataURL image export rather than clearly documenting a production PNG-plus-standalone-SVG workflow, and no comparable ARIA graph-semantic guidance was found. [G6 repository/features](https://github.com/antvis/G6) · [ComboCombined layout](https://g6.antv.antgroup.com/en/manual/layout/combo-combined-layout) · [Renderer options](https://g6.antv.antgroup.com/en/manual/further-reading/renderer) · [Export API](https://g6.antv.antgroup.com/en/api/export-image) · [Releases](https://github.com/antvis/G6/releases)

## Implementation constraints carried forward

- Integrate one yFiles `GraphComponent` per C4 layer inside a Lit-owned container/custom element; destroy listeners and component state in Lit teardown.
- Use the viewer/read-only input mode. Node activation drives drill-down; do not enable semantic mutation gestures.
- Start with SVG rendering and Hierarchical Layout configured for group nodes and orthogonal edges. Add level-of-detail label hiding before considering Canvas/WebGL2.
- Export from the same projection and visual-style functions used onscreen: `SvgExport` for SVG, then the documented bitmap path for PNG. Test full-graph and viewport export, transparent/opaque dark backgrounds, embedded fonts/icons, and maximum dimensions.
- Provide a DOM/ARIA companion (navigable node list or tree plus inspector), visible graph focus, keyboard selection/drill-down, and live announcements. Do not claim WCAG conformance from engine choice alone.
- Gate implementation on a yFiles evaluation spike and license approval. The spike must use the actual Lit/Vite build, a representative 500-node compound C4 fixture, representative edge density/labels, worker or asynchronous layout behavior, both exports, and the accessibility companion.

## Gaps

- yFiles’ exact production bundle size cannot be established from public docs; measure the licensed/evaluation ESM build in BaiZeArchitect’s Vite route chunk.
- No vendor benchmark matches BaiZeArchitect’s actual 500-node compound C4 shape. A representative spike remains required for layout latency, pan/zoom frame rate, memory, and export time/size.
- License price depends on developer/application scope and must be obtained through yWorks’ configurator or sales process.
- If commercial licensing is rejected, SVG export becomes an explicit product/engineering decision before the Cytoscape.js fallback can be declared implementation-ready.
