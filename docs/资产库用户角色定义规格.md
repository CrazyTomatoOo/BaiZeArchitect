## 背景与目标

用户角色（Actor / 业务参与者）成为 workspace 级一等可复用资产（第四类 ReusableAsset kind=`actor`），场景/用例资产通过**浮引用**（assetId）引用参与者，替代自由字符串。本规格只覆盖资产库层，**不修改设计阶段 Artifact schema**（`artifact-content-v1` 不动）。

**术语**：Actor（业务参与者，资产 kind=actor，中文「参与者」）与 Agent 角色（Role Contract，Orchestrator/Analyst/Architect/Critic）及操作者身份（可信 Actor/ActorRef，中文「操作员」）明确区分。见 CONTEXT.md 消歧说明。

## 1. 角色资产 Schema（`asset/actor/v1`）

| 项 | 契约 |
|---|---|
| kind | `actor` |
| 身份 | 仅 store 级 `assetId`；content 无 slug id |
| content | `{ name: string(必填非空), description?: string(可空→"") }`，additionalProperties: false |
| title | `title = content.name` 镜像：创建同步、PATCH 改名同步 |
| 唯一性 | workspace 内 `trim + 大小写不敏感` 归一化后唯一；冲突（创建/PATCH）→ `409 name_conflict` |
| 治理 | 纯资产库操作；不触发审批/readiness/workflow 事件；审计与现状一致（不记 actorSnapshot） |

## 2. 引用形状与校验

### 形状（同字段不同形状）

```jsonc
// scenario（新）— 浮引用
{ "actors": [{ "assetId": 3 }] }
// usecase（新）
{ "actor": { "assetId": 5 } }
// function — 无参与者字段，不受影响
// 存量 — 兼容展示：{ "actors": ["管理员"] }
```

浮引用语义：content 只存 assetId，展示时解析 **最新 revision**。

### 校验

- **位置**：operator-server 的 create / import 分支；store 保持宽松。
- **强制范围**：人工 create 与 import。**归档宽准入**：workflow archive → ReusableAsset 不转引用、不校验（Engine 确定性执行）。
- **导入批内自包含**：批内先建/重映射所有 kind=actor，再建 scenario/usecase；校验视野 = 本批新建 + 存量。
- **错误**：`400 { error: "invalid_actor_ref", invalidRefs: [{ assetId, path }] }` — 聚合全部无效引用，无部分写入。

## 3. API 契约

| 端点 | 语义 |
|---|---|
| `PATCH /api/assets/:id`（仅 kind=actor） | body `{name?, description?}` 至少一项；追加新 revision（revisionNo 递增 + digest 重算），title 随 name 同步，返回 `200 {revisionId, revisionNo}`；`{}`→400；重名→409；非 actor/不存在→404；无乐观锁 |
| `DELETE /api/assets/:id` | 删前扫同 ws scenario/usecase **current revision** 引用；被引用→`409 { error:"asset_referenced", refs:[{kind,assetId}] }`；未引用→`200 {deleted:true}`；同事务 |
| `GET /api/assets/export` | 数组形状不变；引用替换为内嵌快照 `{assetId, name, description}`；旧字符串原样 |
| `POST /api/assets/import` | 内嵌快照按 name（trim+大小写不敏感）复用或新建 actor，重写引用方 assetId；快照不作覆盖源；新角色 source=import；随后按 §2 校验 |
| `GET /api/assets/:id` | **后端 enrich**：含引用的 scenario/usecase 附带 `resolvedActors: [{assetId,name,description}]`，content 本体不动；旧字符串 shape 原样 |

## 4. UI 落点（`baize-asset-library`）

- 「参与者库」tab（KINDS 增加 actor）。
- 新建：actor → 结构化双字段表单（名称必填/描述选填）；其余 kind 维持 JSON/纯文本 textarea。
- 新建/编辑场景用例时表单下方显示「可用参与者」只读提示（id+name，粘贴 assetId）；`invalid_actor_ref` 按 path 逐条红字。
- 详情三态渲染：① 引用+resolvedActors → 名称+最新描述清单；② 存量字符串 → 原文；③ 悬空（理论不发生）→ 占位「参与者 3（已不存在）」；content JSON 保留 `<pre>` 块。
- 空态沿用现有模式；参与者库补充「请先新建参与者，再在场景/用例中引用它」。
- 删除被引用 actor → 「该参与者被以下资产引用,无法删除」+ 引用方标题（assetId 翻译）。
- 前端类型：kind 联合加 `'actor'`；`AssetDetail` 加可选 `resolvedActors`。导出/导入 UI 格式不变，快照嵌/重映射后端透明。

## 5. 测试矩阵（机器资产内定义，实现阶段驱动执行）

| 维度 | 变量（判据） |
|---|---|
| actor CRUD | create 201+rev1；PATCH name→新rev+title同步；PATCH desc→仅desc变；PATCH 重名→409；唯一性 trim+大小写；PATCH 空 body→400 |
| 引用校验 | 新建强制→invalid_actor_ref；存量宽松通过；聚合错误 invalidRefs 全列；批内自包含先 actor 后引用方 |
| 禁删 | 被引用→409 asset_referenced+refs；未引用→200 |
| 导入重映射 | 同名复用 assetId（不覆盖定义）；新名新建 source=import |
| 导出形状 | 引用→内嵌快照；旧字符串→原样 |
| 归档 | 宽准入：不转引用、不校验 |
