# M0 演示 FAQ

## 1. 没有真实企业仓库，M0 还有意义吗？

有意义，但边界必须说清楚。

当前 M0 证明的是技术链路可运行：需求案例、代码证据、结构化 Artifact、决策记录、追踪矩阵和 Design Package 可以被统一组织和校验。

当前 M0 不证明：该方案已经适配真实企业存量系统，也不证明模型能自动产出高质量设计。

## 2. 为什么不直接等真实仓库？

因为真实仓库通常涉及权限、脱敏、代码边界和组织协调。等待期间可以先证明核心契约是否合理。

如果本地 PoC 的证据格式、Artifact 结构和归档方式都无法讲清楚，接入真实仓库只会放大问题。

## 3. 本地 `pilot-backend` 会不会太假？

它是样例仓库，不是真实企业复杂度替代品。

它的作用是提供最小但真实的 Git、文件、符号和行号证据。也就是说，校验器确实在验证一个真实本地仓库，而不是验证纯文本占位符。

## 4. 这个 PoC 和普通文档生成有什么区别？

区别在于它强制保留机器可校验的结构：

- 需求不是散文，而是 `RequirementSpecification`。
- 架构不是自由文档，而是 `ArchitectureSpecification`。
- 决策不是一句结论，而是 `DecisionRecord`。
- 代码引用不是截图，而是 `repositoryId + commitSha + filePath + symbol + lineStart + lineEnd`。
- 归档不是压缩包，而是带 manifest 和追踪矩阵的 Design Package。

## 5. 历史校验器验证了什么？

旧 M0 校验器已在当前 Gateway/SQLite 重构中移除。历史记录曾覆盖：

- Schema 文件和案例数量。
- 代码证据中的仓库、commit、文件、行号和符号。
- Artifact、Design Package 与追踪矩阵的引用关系。

这些结论仅作为 M0 历史评审材料保留，不应作为当前可执行命令。

## 6. 当前校验器没有验证什么？

没有验证：

- 设计是否业务正确。
- 模型输出是否稳定。
- 代码索引是否覆盖复杂调用关系。
- Artifact 是否已经达到生产级 Schema。
- 审批、审计、权限和运行恢复。
- 真实企业系统中的复杂边界。

这些需要真实试点和 M1 之后的平台能力。

## 7. 为什么曾经支持 `--repo-root`？

旧校验器曾允许把案例中的 `repositoryId` 映射到外部本地仓库路径。该入口已随校验器删除；本节仅解释历史设计，不提供可执行命令。

## 8. 没有真实仓库时，演示结论应该怎么说？

推荐说法：

> M0 本地 PoC 已证明需求、代码证据、设计产物、决策、追踪和归档校验这条链路可运行。当前结论只支持进入真实仓库试点，不支持直接进入全面平台建设。

不推荐说法：

> M0 已证明系统可以用于企业生产。

## 9. 什么时候可以进入 M1？

建议至少满足：

1. 有一个真实 Java/Go 企业仓库完成同样验证。
2. 有 5 个真实历史需求替换当前样例案例。
3. 架构师确认至少 2 个 Artifact 可作为设计评审输入。
4. 人工大幅重写比例不高于 30%。
5. 证据引用被评审认为可信。
6. Artifact Schema v0.2 冻结。
7. Platform API 技术栈已决策。
8. Agent Runtime 独立服务边界已决策。

## 10. 如果长期没有真实仓库怎么办？

可以继续增强本地演示仓库，但不要把它当作真实试点结论。

可增强方向：

- 增加更真实的 Controller/Service/Repository 分层。
- 增加测试。
- 增加 OpenAPI 草案。
- 增加更多 SQL migration。
- 增加模拟历史需求和评审记录。

但最终仍需要真实仓库验证，否则无法证明企业存量系统适配能力。

## 11. 评审时最容易被问的问题是什么？

### 问：这个是不是只是手写样例？

答：Artifact 是手工样例，但证据链是真实校验的。M0 本阶段验证的是结构和链路，不验证自动生成质量。

### 问：为什么不先做 UI？

答：UI 之前必须先证明 Artifact、证据、决策和归档契约稳定，否则 UI 会固化错误抽象。

### 问：真实仓库复杂调用链怎么办？

答：M0 后续需要接 Code Knowledge Service。当前证据格式已经为 commit、文件、符号、行号和 claim 预留了稳定接口。

### 问：模型如何接入？

答：M0 当前使用人工样例隔离模型不确定性。M1 前需要补 Agent Runtime PoC，把模型输出写入相同 Artifact Schema。

## 12. 演示通过后的正确下一步是什么？
M0 演示材料仅供历史评审；若启动新的试点，应使用当前 Gateway/SQLite 流程和根目录 `README.md` 中的测试入口，不再替换案例后运行旧校验器。
