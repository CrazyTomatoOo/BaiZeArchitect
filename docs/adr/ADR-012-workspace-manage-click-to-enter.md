# 工作区管理页条目点击进入（反转 #85 概念分离）

工作区管理页 `/manage` 的列表条目整卡可点击，点击即进入该工作区（设 workspaceId + 写 localStorage + 导航到 `/`），与首页选择器「进入」行为一致。当前工作区条目以 accent 左条 + accent-glow 背景标识。管理页顶栏不再渲染工作区切换器——条目点击是管理页的唯一进入途径。

## 背景与反转理由

Issue #85 决策 10 将「选择工作区」和「管理工作区」分离：选择器（`/`）负责"选"，管理页（`/manage`）纯 CRUD，列表行移除「进入」按钮。反转原因：操作员在管理页浏览工作区列表时，「看到条目 → 想进入」是直觉动作；强制绕回选择器或顶栏切换器增加了无意义的导航开销。条目点击是**补充入口**，不取代选择器——选择器仍是首次登录/无工作区时的默认入口。

## 交互细节

- 整卡可点击；删除按钮 `stopPropagation`，不误触进入。
- 键盘可达：`role="link"` + `tabindex="0"` + Enter/Space 激活（仅当事件目标是卡片本身，避免删除按钮按键冒泡触发进入）。
- 点击当前工作区照常进入（幂等，无特殊分支）。
- 管理页 chrome：Activity Bar / Side Bar / Panel / 顶栏切换器全部隐藏（切换器在管理页与条目点击冗余）。

## Considered Options

- **恢复独立「进入」按钮**（#85 前的原始设计）：拒绝——整卡点击区域更大、交互更直接，且管理页条目信息密度低（仅名称 + 路径），不需要独立按钮占用行内空间。
- **保留顶栏切换器作为并行入口**：拒绝——管理页同时存在切换器和可点击条目是冗余入口，且切换器显示"当前工作区"与管理页的全局管理语义不符。
