# Workspace deletion cascades through its full governance subtree

Status: accepted（实现于 `9746f52`；决议来源 `.scratch/workspace-management/map.md` 票 07/08/10）

BaiZe workspaces exist as registry rows (`workspaces`: repo_path unique, name) with all governance data scoped to them — requirements, workflows, events, receipts, incidents, plans, attempts, runs, findings, decisions, approval packets, design packages and reusable assets all carry `workspace_id`/requirement- or workflow-scoped foreign keys (`on delete restrict`). Earlier wayfinder drafting (2026-08-16) proposed soft archive (`archived_at`, reversible, read-only); the destination was redrawn on 2026-08-18 with the user decision: **deletion is cascade and irreversible** — a workspace is retired by destroying its whole subtree in one transaction.

Decision: `DELETE /api/workspaces/:id` hard-deletes 33 tables reverse-topologically in a single transaction, suspends and restores the 22 delete-blocking triggers in-transaction (DDL sourced live from `sqlite_master`), skips `snapshot_documents` (content-addressed, digest-shared across workspaces, immutable), and runs `PRAGMA foreign_key_check` after commit. Deletion is refused with `409 workspace_busy` while any Run is `queued`/`running` or any governance Claim is `active` under the workspace; the Web UI requires an explicit two-step inline confirmation. No capability gating is added — the server currently enforces no capabilities and per-workspace ACL is out of scope. No migration is needed: SQLite `on delete cascade` cannot bypass the child-table delete triggers (verified empirically) and would force rebuilding ~22 tables, while arming every future parent delete to silently cascade.

Consequences: destruction is intentional and permanent — no recycle bin, archive, or restore path; Outbox jobs for the workspace die in the same transaction (undelivered events are lost by design); `snapshot_documents` rows orphan but accumulate only bounded by `unique(kind, digest)` dedup (a future GC would need to suspend the immutable-delete trigger and reference-count); design-session and run transcript `.jsonl` files orphan on disk (best-effort GC; `repo_path` directories are user-owned and never touched). Startup reconciliation hard-fails on any FK violation, so the delete must stay all-or-nothing — verified by re-opening the Store after a full-workspace delete test fixture.
